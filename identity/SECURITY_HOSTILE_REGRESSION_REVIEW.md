# Identity hostile regression review

This document records R5 of the August 2026 Identity security-remediation roadmap: a finding-by-finding hostile regression review of the original 20 confirmed findings against the current package.

The review does not treat a merged remediation PR as proof by itself. For each finding, it compares the original exploit condition with the current production path and the available regression/integration coverage.

## Verdict legend

- **Blocked** — the original exploit condition is no longer reproducible at the package level and regression coverage protects the invariant.
- **Accepted tradeoff** — the original observation remains by design and is not treated as a security defect.
- **Package verified; deployment confirmation pending** — the package-level control exists, while correct operation still depends on host deployment configuration.

## Finding-by-finding review

| Finding | Original security invariant / exploit | Current production evidence | Regression evidence | R5 verdict |
| --- | --- | --- | --- | --- |
| C-1 | Concurrent OTP verification must not bypass `max_attempts` or consume one OTP more than once. | `VerifyOtpService` reads the challenge through `get_for_update()`; failed attempts use repository-level atomic `attempts_count + 1`; successful consumption and session creation stay inside one transaction. | `tests/integration/application/services/test_verify_otp_concurrency.py` proves parallel valid verification creates one session and parallel failures do not lose attempts on PostgreSQL. | **Blocked** |
| H-1 | An unauthenticated requester must not be able to keep a victim from obtaining a usable challenge ID. | `RequestOtpService` returns the same active challenge metadata during resend cooldown instead of rejecting the later requester; `get_latest_active()` excludes consumed/expired challenges. | `tests/application/services/test_otp_cooldown_security.py` proves repeated requests return the same usable challenge without resending and consumed challenges do not block a new request. | **Blocked** |
| H-2 | Refresh rotation must be atomic, detect reuse, revoke the active family, and preserve a fixed absolute family lifetime. | `RefreshSessionService` locks refresh-token rows, detects reuse of replaced sessions, revokes the family, and carries forward `family_expires_at`. | `tests/integration/application/services/test_refresh_session_concurrency.py` validates single rotation, reuse/family revocation, and fixed family expiry on PostgreSQL. | **Blocked** |
| H-3 | Unsupported OTP purposes must not enter an authentication/session-issuance path. | Public request schema accepts only registration/login; `OtpPurposePolicy` is default-deny; `VerifyOtpService` has explicit registration/login branches and rejects everything else. | `tests/presentation/test_fastapi.py` rejects unsupported public purposes; service security tests cover unsupported-purpose behavior. | **Blocked** |
| M-1 | Suspended, disabled, or otherwise non-active users must not create or continue authenticated sessions. | Login verification applies `UserStatusPolicy.ensure_active()`; JWT authentication reloads the user and enforces the same policy for existing access tokens. | `tests/application/services/test_user_status_security.py` and `tests/infrastructure/security/access_tokens/test_jwt_access_tokens.py` cover non-active users. | **Blocked** |
| M-2 | Anonymous callers must not have a direct registration-state oracle at OTP-request time, and bulk enumeration must be abuse-limited. | OTP request no longer rejects solely because registration state mismatches the requested purpose; registration/login validity is enforced only after possession of the delivered OTP. | M-3 | OTP request/verify abuse must be rate-limited by semantic scopes that cannot be trivially bypassed by destination or requester representation changes. | Application-level destination burst/daily, requester/IP, and challenge verify limits exist; destination and IP values are canonicalized before bucket selection; distributed limiter injection and edge throttling responsibilities are documented. | Policy, service, IP-normalization, request-metadata, and R3 regression tests cover daily limits, cross-destination requester limits, normalized destinations, equivalent IPv6 forms, and malformed forwarded metadata. | **Package verified; deployment confirmation pending** |
| M-4 | HMAC/JWT secrets must reject weak short values. | HMAC key validation and JWT codec construction both require at least 32 bytes; HMAC key IDs are validated. | `tests/infrastructure/security/test_hmac_hasher.py` and `tests/infrastructure/security/access_tokens/test_jwt_access_tokens.py` reject short secrets. | **Package verified; deployment confirmation pending** |
| M-5 | Canonical identity representations must prevent duplicate identities and abuse-bucket bypass; malformed destinations must be rejected. | Email normalization applies NFKC, casefolding and control/whitespace rejection; mobile normalization maps Unicode decimal digits, handles `00` international prefix, removes allowed separators, and enforces E.164. | `tests/infrastructure/security/test_identity_normalizer.py` covers canonical forms, malformed values, Arabic-Indic digits, and explicit direction-control rejection; rate-limit service tests cover normalization-based bucket sharing. | **Blocked** |
| M-6 | Client-supplied HTTP body fields must not control forensic IP/device metadata. | Verify/refresh public schemas contain no IP/device fields; FastAPI resolves metadata server-side through `RequestMetadataResolver`; direct mode ignores forwarding headers and trusted-proxy mode validates/canonicalizes the configured forwarded hop. | `tests/presentation/test_fastapi.py`, `test_request_metadata.py`, and `test_ip_address.py` cover forged body values, direct-peer behavior, trusted hops, malformed addresses, and IP canonicalization. | **Package verified; deployment confirmation pending** |
| M-7 | Security-relevant failures and recovery actions must produce structured, non-secret events. | `SecurityEventSink` and typed event names cover OTP failures/limits, refresh reuse, and session revocation; event payloads contain IDs/fingerprints rather than OTPs, raw tokens, secrets, or raw destination PII. | `tests/application/services/test_security_events.py` and related rate-limit/revoke tests verify event emission. | **Package verified; deployment confirmation pending** |
| M-8 | A compromised user must have a supported way to invalidate all active sessions. | Authenticated `/identity/sessions/revoke-all` invokes `RevokeAllSessionsService`, which performs one repository-level bulk revoke and emits an event. Session listing remains an optional product feature rather than a closure requirement. | `tests/application/services/test_revoke_all_sessions_security.py` proves all user refresh sessions are invalidated; presentation tests require authentication. | **Blocked** |
| M-9 | Expired/consumed OTP challenges and expired/revoked sessions must not grow without bound. | Configurable retention policy and bounded repository deletes are exposed through `CleanupRetainedIdentityDataService`; scheduling remains host-owned. | `tests/application/services/test_data_retention_cleanup.py` verifies only eligible old records are deleted and batch bounds are respected. | **Package verified; deployment confirmation pending** |
| L-1 | The reusable JWT codec must reject expired tokens itself. | `PyJwtHmacCodec.verify()` uses normal PyJWT expiration verification and no longer disables `exp`. | `tests/infrastructure/security/access_tokens/test_jwt_access_tokens.py::test_pyjwt_codec_rejects_expired_token`. | **Blocked** |
| L-2 | Notification failure must not commit a challenge that causes cooldown without delivery. | OTP challenge creation, notification dispatch, and commit are ordered so a dispatch exception exits before commit. | `tests/application/services/test_otp_notification_consistency.py` proves a failed first send can be retried immediately and triggers another send attempt. | **Blocked** |
| L-3 | Unexpected authentication/backend failures must not be masked as invalid credentials/HTTP 401. | `AuthenticatedUserDependency` catches only `AccessTokenAuthenticationError`; JWT authenticator converts only token/authentication-domain failures and lets unrelated infrastructure errors propagate. | `tests/presentation/test_authentication_dependency.py` explicitly verifies backend `RuntimeError` is not converted to 401. | **Blocked** |
| L-4 | Public/model members must not imply security behavior they do not implement, and compatibility fields must not become alternate authoritative security state. | Unused permission/transaction APIs were removed; `MODEL_SEMANTICS.md` defines canonical versus compatibility fields. Current OTP lookup uses `normalized_destination`; identity lookup/uniqueness uses normalized values. `last_used_at` is documented as refresh-use metadata, not general authentication activity. | Existing mapper/model/security-flow tests exercise canonical fields. R5 corrected stale `last_used_at` documentation to match refresh behavior. | **Blocked** |
| L-5 | Authenticated requests currently perform database-backed session validation on each request. | `SqlAlchemySessionReader` still performs a database lookup per authentication, intentionally preserving immediate revocation semantics. | Existing access-token tests validate the database-backed contract behavior; no security remediation is required. | **Accepted tradeoff** |
| L-6 | The OTP latest-active hot path needs an index matching destination + purpose + recency. | SQLAlchemy metadata defines `ix_identity_otp_challenges_destination_purpose_created_at` on `(normalized_destination, purpose, created_at)`. Host migration requirements are documented. | Metadata/index regression coverage and migration documentation protect the index shape. | **Package verified; deployment confirmation pending** |
| L-7 | HMAC key rotation must preserve valid overlap credentials without indefinite old-key trust. | New hashes are versioned by key ID; current and explicitly active previous keys are separated; legacy hashes are migration-compatible; refresh lookup uses all active hash candidates; compromised-key procedure requires immediate retirement/revocation. | `tests/infrastructure/security/test_hmac_hasher.py` covers current/previous keys, legacy hashes, retired/unknown keys, bad key configuration, and minimum secret length; refresh security tests cover continuity. | **Package verified; deployment confirmation pending** |

## Review conclusions

1. **No original Critical or High finding is reproducible in the reviewed package paths.** C-1 and H-2 additionally have real PostgreSQL concurrency validation rather than SQLite-only evidence.
2. **No original Medium or Low package-level exploit was found to have regressed.** L-5 remains the explicitly accepted database-lookup tradeoff.
3. R5 found one stale documentation statement for `Session.last_used_at`; it was corrected to reflect that successful refresh rotation records refresh-token use on the rotated session while ordinary access-token validation does not update it.
4. R5 added explicit regression cases for left-to-right/right-to-left direction-control characters in identity normalization because the original M-5 audit called out these representations directly.
5. Deployment-dependent controls are not considered proven by package tests. Before operational closure, the host must still confirm shared/distributed rate limiting where required, trusted-proxy/edge configuration, real security-event routing/alerting, retention scheduling, production migrations/indexes, secret storage/quality, and HMAC rotation procedures.
6. **R6 remains required:** perform a fresh hostile review that is not limited to the original 20 findings and look for new vulnerabilities or unsafe interactions introduced by remediation work.

## R5 completion gate

R5 is considered complete only after the full quality suite, including PostgreSQL integration tests, passes on this review branch. The roadmap should be marked complete only after that validation succeeds.
